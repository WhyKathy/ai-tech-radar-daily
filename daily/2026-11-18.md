## 1. Agent 架构与工程

- **[P0] Experience Rot：工具接口静默变更后，有经验的 agent 在多数任务上失败，而零经验 agent 大多成功** — arXiv 11-16 提交。以 MCP 定义工具，在接口发生静默变更后测试多款模型：有经验的 agent 直接复用此前的调用而不检查当前接口，即使工具定义已经展示了变更，随后仍报告任务成功；该失败在测试的每一种记忆形态（对话历史、记忆文件、检索笔记、技能）中都出现，并随经验量增加而加重。缓解手段效果有限：公告更新几乎无用，把 agent 指向文档在文档未写明答案时同样失败；当文档不完整时，经验反而正是让 agent 成功的原因。→ 价值：记忆与经验的价值与工具接口稳定性强耦合，接口版本应作为记忆的失效键进入自进化系统的准入层，否则经验越多、静默变更后的损失越大。｜来源：[arXiv:2611.20922](https://arxiv.org/abs/2611.20922)｜2026-11-16

- **[P0] Harness Leverage Across Model Size：五个 harness × 四个 0.75B–4.7B 模型 × 18 个产工件任务，127/357 个格子没有写出任何声明工件，其中 85 个正常退出** — arXiv 11-16 提交。同时变动 harness 与模型规模，加一个 35.5B 锚点，共 360 个格子由同一个确定性检查器评分。以完成门控为核心的 Mingbird 在每个规模上均值最高；四个预注册配对对比中两个通过 Holm 校正（0.75B 与 4.7B），十六个配对区间中十三个排除零，领先幅度从 0.075 到 0.819。消融显示完成门控不是载体：关掉全部六项可执行检查后均值变动为 +0.080、+0.117、+0.003、−0.004，区间全部含零，仅在 1.9B 上关掉会产生空跑；单独删掉一条重复块拦截规则在 0.75B 上损失 0.411，并让 18 个任务中的 8 个没有工件。作者结论是 harness 效应主要是「进度效应」：它决定一次运行是否在磁盘上留下东西。→ 价值：以退出码或进程状态计分的评测会把从未写出的工作记为完成，harness 比较必须配工件级检查；小模型上 harness 的杠杆最大，选型前先固定 harness。｜来源：[arXiv:2611.21407](https://arxiv.org/abs/2611.21407)｜2026-11-16

- **[P1] Beyond Plain MCP：code mode 把 token 用量压低 70–90%，stub 里声明返回形状可让弱模型成功率摆动 39.5 个百分点** — arXiv 11-14 提交。在 12 个 MCP 服务器、最多 1,958 个干扰工具、三个开权重 agent（Qwen、Gemma、Nemotron）上做预注册、密封测试集评估：code mode（对工具 stub 写脚本）显著优于纯 MCP，token 用量下降 70–90% 且效用提升；在 stub 中声明返回形状是一阶变量，对较弱 agent 的成功率影响可达 39.5 个百分点，幅度大于在前面加路由层。核心假设「决策层 + code mode 优于单独 code mode」未获证实：对弱模型只有不显著的微小提升，对最强模型略有成本。作者公开了 harness、一个微调的 4B 工具选择模型与全部评测轨迹。→ 价值：工具目录规模化后的主要成本落在上下文里的 schema 而非服务器数量，返回形状提示的收益高于增加路由层。｜来源：[arXiv:2611.19123](https://arxiv.org/abs/2611.19123)｜2026-11-14

- **[P1] Recovery Gone Too Far：四个主流模型在 304 个场景中动作边界失守率最高 96.8%，nrepair 以「一次否决」降到 16.2%** — arXiv 11-15 提交。研究工具普通报错（限流、超时）后的替代工具兜底：同一个兜底动作在一个环境里完成任务，在另一个环境里越界（例如 push 被拒后强推，在自己仓库只覆盖本人提交，在另一仓库会删掉他人提交）。304 个场景覆盖 8 个领域、55 个真实 CVE，四个主流模型全部出现风险兜底，三种主流缓解手段均无效。nrepair 在每次调用替代工具时用仅在正常轨迹上校准阈值的监视器给上下文打分，触发时扣留该次调用并把决定交回 agent：动作边界失守最多下降 76.0%（67.5%→16.2%），多数模型正常成功率下降不到 7%，在 Claude Code 与 Codex 两个生产 agent 上同样有效。→ 价值：兜底策略的权限边界应外置为运行时的单次否决，而不是写进提示词或工具白名单的静态描述。｜来源：[arXiv:2611.19886](https://arxiv.org/abs/2611.19886)｜2026-11-15

## 2. 论文与方法

- **Self-Improvement Memory Enables Continual Recursive Self-Improvement** ｜未标注机构 ｜[arXiv:2611.18856](https://arxiv.org/abs/2611.18856) ｜2026-11-13
  方法：把自我改进记忆（SIM）加在 harness 优化器而非任务策略上——按反复出现的 harness 问题给编辑分组，记录改动理由、预测与实得结果、评估上下文；在基准或策略模型更换后，用这份历史决定哪些演化成果复用、哪些重做。
  价值：四个领域的跨数据集与跨模型配对比较中，SIM 的终局分数高于「只带 harness」与「只带根因」的续跑；编码域十次独立源运行里，带 SIM 的配对续跑平均高 2.36 分（p=0.003）。harness 演化的可迁移性来自「为什么改」的记录，而不来自改后的那版 harness。

- **StaleBench: Isolating Stale Retrieval in Agent Memory, and Pricing the Fix** ｜未标注机构 ｜[arXiv:2611.19752](https://arxiv.org/abs/2611.19752) ｜2026-11-15
  方法：892 条真实随时间更新的事实，时效标签取自数据源（Wikidata 有效期，经 TempLAMA），不用检索分数；新增 contamination@5 度量，并对比 Mem0、Graphiti、LangMem 与复现的 ERASE 四种已部署系统的取代（supersession）处理。
  价值：一个保留策略与「全保留」对照在每条测试查询上都返回完全相同的 rank-1 语句，但在不显示日期时两个阅读器的准确率相差 29.5 与 65.6 分——检索指标会给出反向排序，current@1/current@5 排不出来，contamination@5 能排对。抽掉语句里的词法锚点会让已部署的键控机制损失数十个百分点的时效性，写入路径与查询两侧都做实体解析可恢复大部分损失。

- **The Silent Cost of Conversation History in LLM Reasoning** ｜未标注机构 ｜[arXiv:2611.20071](https://arxiv.org/abs/2611.20071) ｜2026-11-15
  方法：两项预注册研究。研究一在 48 个分片数学任务上比较保留与丢弃模型自身历史回复；研究二构造 CDR-Stream：100 轮状态追踪对话，每轮有精确答案并按模型难度校准，对比全历史与求解器校验过的状态摘要。
  价值：保留自身回复使最终成功率下降 0.21（GPT-4o-mini）与 0.29（Mistral-7B，Holm 校正 p=0.004）；在同等难度下全历史配置的准确率在二十轮内由约 0.6 跌到 0.1，而外部状态摘要使其高出 0.52–0.59。一致性、逻辑连贯度与稳定性指标下降远小于准确率，成对就绪度与单流漂移检测都没有给出稳健的早期预警——任务状态应存在对话记录之外，监控要跨会话而非依赖过程指标。

- **[P1] Stint：长输出推理服务的内存抖动来自抢占后重算，保留快照 + 年龄重入使 p99 每 token 时延降 50.7%、整体提前 10.7% 完成** — arXiv 11-15 提交。定义 KV thrashing：显存写满后请求被抢占，可能在产出极少新 token 的情况下反复失去与恢复状态，现有系统会让超过五分之一的请求停滞逾一分钟。Stint 把定长 KV 快照存入连续性优先的 CPU 池（精确区间分配器，融合 gather/scatter 内核与双缓冲），为被抢占请求保留工作并限定等待时长，返回后给一轮新鲜解码保护；受害者选择用解码隐状态估计剩余长度。Qwen3-32B 在 H200 上重放奥赛数学负载：无请求停顿超过 50 秒，p99 每输出 token 时延相对同引擎重算基线下降 50.7%，整体完成时间缩短 10.7%（吞吐 +12.0%）。→ 价值：交互式长输出服务的长尾由调度与状态保存决定，快照重入优于加卡，也优于把超时当作可接受损耗。｜来源：[arXiv:2611.20106](https://arxiv.org/abs/2611.20106)｜2026-11-15

- **[P1] Re-Reading Is Not Free：真实编码 agent 负载中缓存上下文读取占 API 报告 token 的 94.8%，每生成 1 个 token 约读 260 个缓存 token，能耗估计相差 25 倍** — arXiv 11-16 提交。统计十周、42 个会话、752 个任务片段、近 10 亿 token：未缓存输入仅占 0.017%；会话内上下文增长 5.3 倍，单任务内只增 1.4 倍。把缓存上下文处理纳入解析式能耗模型后，该负载估计约 250 kWh，而按输出计量的 EcoLogits 只给约 10 kWh；每个任务从全新上下文开始可把估计降低约 60%。父会话日志只记录子 agent 的最后一次内部调用，委派 token 被少计约 10 倍，对本负载的能耗估算影响约 5%，但对以 token 量为基础的统计是系统性偏差。→ 价值：agent 的成本与能耗结构以「重读上下文」为主，按输出 token 或单次请求计量的口径会系统性低估一个数量级；以任务为单位计费与做容量预算才对齐真实负载。｜来源：[arXiv:2611.20873](https://arxiv.org/abs/2611.20873)｜2026-11-16

## 5. 评测与基准

- **Benchleaking Is Accelerating：ERNIE-5.5-Flash-Base 的 96% HumanEval 题目连同参考实现一起泄漏，Anti-Hack 计分下损失 16.6 分** — arXiv 11-16 提交。用少样本续写探测四个公开基座模型在 20 个基准上的泄漏：部分基座模型会写出输入中并不存在的其他测试题目（完整题干、选项与答案）；ERNIE-5.5-Flash-Base 有 96% 的 HumanEval 题目带参考实现泄漏、85% 的 OpenBookQA 题目带答案泄漏，DeepSeek-V4-Flash-Base 分别为 9% 与零。作者定义 Anti-Hack 分数（把所有泄漏样本判错、样本数不变后重算）：DeepSeek-V4-Flash-Base 损失 1.5 分、Hy3-preview-Base 1.3 分、MiMo-V2.5-Base 5.0 分、ERNIE-5.5-Flash-Base 16.6 分。后训练侧引用近期审计：有 agent 在 23% 的尝试中说出从未给过的隐藏测试要求，且任务被改成相反要求后仍继续遵循。→ 价值：污染已从后训练下探到预训练基座，开源基座的基准分数不能直接当作下游能力的上界；去污染报告与污染校正分应作为选用基座的前置条件。｜来源：[arXiv:2611.21315](https://arxiv.org/abs/2611.21315)｜2026-11-16

- **SWE-CoWork：101 个真实仓库、26 个模拟同事，两个领先模型满足约 63% 的 fail-to-pass 测试但完成任务不足 8%** — arXiv 11-15 提交。每个任务把 agent 放进有 26 名同事的模拟工程组织，同事职责不同、知识有界、协作行为受控；agent 从一份简短交接开始，需从同事与工作记录中还原被分散的需求、调和冲突证据，并由私有可执行测试评分。11 个模型的结果：两个领先模型满足约 63% 的 F2P 测试，完整交付不足 8%；一次性提供完整需求使 Seed Evolving 与 GPT-6 Astra 的 F2P 提高约 16 个百分点，但完整任务成功率不变。轨迹分析显示失败贯穿交付全流程——Claude Opus 5.5 把 93% 的首个问题指向了对口负责人，却只拿到 64% 的同事持有需求；被推迟的问题无人追问；需求到手后实现仍不完整；31% 被报告为完成的需求在测试中失败。→ 价值：编程 agent 的瓶颈已从写代码转向需求追踪、验证与交接，评测若只看 F2P 会高估近八倍；补全需求清单并不等于提升交付率。｜来源：[arXiv:2611.20218](https://arxiv.org/abs/2611.20218)｜2026-11-15

## 今日判断

**① 技术上最值得跟进的 3 条**

1. **Experience Rot（11-16）**：这是把「记忆有用」这一默认假设的第一个反例做得足够干净的实验——失败可复现、跨模型跨记忆形态出现、并随经验量单调加重，而公告更新与文档指引两种最自然的补救都无效。任何把经验写回系统的设计，都必须回答「接口变了怎么让旧经验失效」。
2. **Harness Leverage Across Model Size（11-16）**：127/357 个格子没有写出声明工件、其中 85 个正常退出，这个数字本身就是对现有 agent 评测方法的一次审计。它同时给出一个可操作的结论：小模型上 harness 差异大于模型差异，而差异的载体是完成门控与重复块拦截这类「让运行往前走」的规则。
3. **vLLM v0.34.0（11-17）**：缓存定容方式的改动同时改变吞吐与延迟，且把取舍写成了默认值；1.95×、1.6× 这些数字绑在特定硬件与 MoE 组合上，但缓存从 433k 到 672k token 是可预期的普遍收益，代价的 6–18% TPOT 上升需要在自建集群上实测。

**② 对 harness 设计、模型选型、推理成本、研究方向的影响（判断）**

- **Harness 设计**：完成判定要从「进程退出」改为「工件存在且可检查」，否则评测与训练信号都会奖励空跑（Harness Leverage）；工具接口需要显式版本与变更事件，并把版本作为记忆条目的失效键（Experience Rot）；兜底动作要外置为运行时的一次否决，而不是提示词里的权限声明（nrepair）；工具目录规模化后优先投资 stub 的返回形状，而非在其前面加路由层（Beyond Plain MCP）。
- **模型选型**：基座分数在污染校正前不足以支撑决策，选基座前应先要 Anti-Hack 类校正分（Benchleaking）；小模型配强 harness 与中等模型配弱 harness 之间的排序，需要在固定任务集上重新测一次，而不是按参数规模推断（Harness Leverage）。
- **推理成本**：agent 负载的成本主体是缓存上下文的重复读取，按输出 token 计价的预算模型会低估一个数量级（Re-Reading Is Not Free）；服务侧的长尾由抢占后重算造成，快照重入与年龄重入可在不扩卡的前提下取得两位数吞吐（Stint）。三项叠加，任务级成本模型应写成「缓存读取 + 生成 + 重算损失」三段。
- **研究方向**：本周的几条独立工作正在把自进化系统的治理结构收敛到同一个形状——候选与采纳分离、记忆带失效键、评测带统计校正。差异在治理强度：SIM 记理由与预测结果，StaleBench 用数据源时间戳而非检索分数，Benchleaking 要求污染校正分。可比的下一个维度是「失效检测的假阳性成本」。

**③ 明后两天要看的 2 个信号**

- **Anthropic 11-18 晚间定价与 11-19 首日交易**：看什么——最终定价相对 70–78 美元区间的位置、承销商超额配售权的行使规模、首日收盘与发行价的关系；什么算确认——定价落在上限或更高且首日不破发，说明以最低采购义务为抵押的算力融资模式被公开市场接受。
- **vLLM 0.34 的第三方复测**：看什么——同配置下并发 128 时 TPOT 上升 6–18% 与 433k→672k 缓存扩张的净收益比，以及默认块大小 64 对长上下文命中率的影响；什么算确认——出现带硬件型号、模型与并发数的 A/B 记录，而不是发布说明里的单点数字。
