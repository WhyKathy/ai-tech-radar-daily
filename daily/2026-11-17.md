## 1. Agent 架构与工程

- **[P0] 《More Agents, More Samples, or More Thinking?》元分析：在与样本数或预算匹配的基线下，多智能体的平均精度差为 −0.042，74% 的可比对比中等于或低于单基线** — arXiv 11-13 提交。综合 9 项实证评估、516 个多智能体配置，按六维资源向量与四级基线阶梯重新计账：对贪心单遍基线（A 类）的精度差整体为负，剔除贡献最大的研究后接近零；对样本数匹配（B 类）或预算匹配（C 类）基线平均 −0.042，多水平随机效应模型在敏感性检验下保持为负；把贪心基线换成采样基线会使多智能体的表观优势平均下移 0.038。结论：当 agent 共享相同证据时通信不增加信息，正收益要求证据分区、外部验证或跨模型误差多样性。附评审清单与 pace CLI 计账工具。→ 价值：给「要不要上多 agent」提供了可执行的验收纪律——先定资源匹配基线再谈通信收益；正收益的三个前提条件可直接当作多智能体架构评审的通过条件。｜来源：[arXiv:2611.17610](https://arxiv.org/abs/2611.17610)｜2026-11-13

- **[P0] ModHarness-RL：把 harness 重铸为随 RL 训练共同演化的可学习程序** — arXiv 11-13 提交。把交互记录为结构化 State（类型化块集合），harness 的两个核心组件成为这些块上的程序：Compression 程序把累积历史组装进模型上下文，Steering 程序在行为偏离时提供引导；RL 训练中从近期轨迹提议候选程序、经执行验证、再在历史轨迹上重放，使 harness 跟随模型行为的漂移演化。在 CodeSearch 上深入研究，并在 ALFWorld 与 BIRD SQL 上分析，模型 1.5B–8B：大多数设置下 held-out 性能超过固定 harness 基线。→ 价值：此前的 harness 演化工作多在推理期或独立评估期进行，这篇把它搬进 agentic RL 的训练环内——「随训练共同演化」要求演化判据用执行验证与历史重放双保险，可直接迁移到自进化训练流水线的准入层设计。｜来源：[arXiv:2611.18533](https://arxiv.org/abs/2611.18533)｜2026-11-13

- **[P1] Co-Sight Harness：三个逾 200 步的生产业务工作流，把控制资产外置并用确定性执行强制，无人值守完成率 50%→100%、端到端时延 440→159 分钟** — arXiv 11-13 提交。不改语言模型，把工作流定义、状态与领域知识移入模型外部的版本化控制资产，由状态机与机器可校验的验收门在执行期强制，独立审计员对 trace 评级，资产仅在回归检查与人工批准后更新。三个部署中超过 200 步的工作流：120 例端到端评估集上无人值守完成率 50%→100%、检索召回 56%→91.67%、情景分析召回 45%→93%；另两个领域由未写资产的团队分别用 4 天与 7 天接管。消融分离了两类失败来源。代码已放。→ 价值：长程业务 agent 的可靠性来自模型外的确定性强制层，而非更强的模型；「资产更新须过回归检查+人工批准」是生产环境中 harness 演化的最小治理闭环。｜来源：[arXiv:2611.17696](https://arxiv.org/abs/2611.17696)｜2026-11-13

## 2. 论文与方法

- **Evidence-Governed Adoption of Self-Generated Updates in Autonomous AI Agents** ｜未标注机构 ｜[arXiv:2611.16378](https://arxiv.org/abs/2611.16378) ｜2026-11-12
  方法：EGE 框架把候选生成与确认采纳分离——冻结候选在新鲜配对审计上评估、要求预注册主目标上的有意义的改进、以参照相对非劣性检验保护已声明能力、在受限金丝雀部署前施加治理约束，并给出针对适应性生成序列的评估器校准同时下界构造。
  价值：自进化系统最危险的环节是「局部增益掩盖对早期基线的退化」；这篇给出了带统计保证的采纳闸门完整配方，候选生成与采纳治理的分离结构与 ModHarness-RL、G-CAST 正在收敛。

- **MIRIX-2.0: Multi-Agent Memory System** ｜未标注机构 ｜[arXiv:2611.12068](https://arxiv.org/abs/2611.12068) ｜2026-11-09（11-16 经 HF Daily Papers 延迟曝光）
  方法：六个类型化记忆 agent 各自维护完整记录，配合 AutoDream 等机制组成多 agent 记忆系统，在五个 QA 基准中的四个上为对比系统中最准。
  价值：LoCoMo 91.4%、LongMemEval-S 72.6%（领先最强基线 14.3 分）；关掉 AutoDream 时对 HyperMem 在单跳/多跳文档 QA 上仍有 31.0/22.0 分增益；作为程序性记忆在 ALFWorld 与 WebShop 达到最高平均成功率，MetaClaw-Bench 49.2% 对 MetaClaw 技能库 44.0%。记忆系统的「保持完整记录+按类型分工」路线在 QA 与程序性两类任务上同时验证。

- **G-CAST: Governed Continual Self-Training for E-Commerce Agents under Evolving Demands** ｜阿里巴巴 ｜[arXiv:2611.17814](https://arxiv.org/abs/2611.17814) ｜2026-11-13
  方法：把生产证据转化为按回报路由、按熵排序的训练数据与受治理的奖励演化，模型更新由累积评估控制下的受治理 checkpoint 切换把关，需求漂移与 harness 演化（新工具、新技能、新流程）双约束下持续自训练。
  价值：已部署在 1688 平台的 B2B 采购 agent「源采」上；在真实生产 agent 上对强自主后训练基线取得更强的新需求适应并更好保留既有行为，消融证实数据编排与受治理奖励演化缺一不可——受控持续自训练从论文走向了生产部署。

- **CarryOn: Learning What to Keep in Context for Long-Horizon LLM Agents** ｜未标注机构 ｜[arXiv:2611.17808](https://arxiv.org/abs/2611.17808) ｜2026-11-13
  方法：轻量上下文管理器把紧凑执行状态与细粒度、带来源链接的证据配对，学习型选择器与自适应保留策略在不增加上下文管理 LLM 调用的情况下保留相关证据；提出 S_α（兼顾资源占用）与单位成功归一化成本 NCS 两个互补指标。
  价值：AppWorld、OfficeBench、Tau2 Telecom 三个基准、三个 LLM actor 上 75.7% 宏平均任务成功率，超最强基线 6.7 个百分点；「摘要省 token 但丢细节、全保留保细节但引入噪声」的两难被「执行状态+可检索证据」结构绕开。

- **Aligning AI Teams** ｜未标注机构 ｜[arXiv:2611.17820](https://arxiv.org/abs/2611.17820) ｜2026-11-13
  方法：在脓毒症分诊、新闻推荐两个软件工程任务与十个咨询提案生成任务上研究单 agent 对齐训练向多 agent 团队的迁移机制与干预手段。
  价值：三点发现——单/团队安全差距不随模型能力上升呈一致趋势；让 agent 互相批评或群聊协调等自然干预不能可靠恢复单 agent 的对齐行为；责任扩散实质性地解释了安全差距。多智能体化不是对齐中性的操作，交出去的权限要有独立的回收设计。

## 3. 推理成本与基础设施

- **[P0] MMFlash：扩散起草器进入多模态投机解码，无损加速最高 3.58×，较 EAGLE-3 高 195.4%** — arXiv 11-13 提交。先提出基于「有无视觉输入时下一 token 分布的 KL 散度」的 token 级视觉依赖度指标：接受率从最低依赖四分位的 46% 降到最高四分位的 22%，且多模态训练后依然存在；据此自适应上加权起草器预测差的视觉依赖 token，长视频输入用稀疏注意力降低冗余计算。跨多模态基准实现无损解码加速 3.58×，较 EAGLE-3 高 195.4%、较 DFlash 高 17.1%。→ 价值：VLM 推理的投机解码此前被视觉依赖 token 的低接受率卡住，这篇给出了测量指标与修复方向；论文自注「Work in process」，第三方复现前按作者口径看待。｜来源：[arXiv:2611.18482](https://arxiv.org/abs/2611.18482)｜2026-11-13

- **[P1] VelServe：用自身迭代时延的实测尾部分配每步 prefill 预算，SLO goodput 达最强基线 2.4–2.9×** — arXiv 11-13 提交。识别聚合与分离式 serving 中的解码抖动：一次抖动拖延批内所有请求，长回复跨数百步，罕见超时也会累积成大量 SLO 违规。VelServe 用每步解码迭代时延的实测尾部校准该步承载的 prefill 量，按 SLO 决定「迟到步」须多么罕见，为误预测与 host 停顿留出余量；余量拖慢 prefill，故最短等待 prompt 优先；分离式部署下按 P99 目标间隔准入。三种注意力家族、多种负载下 Qwen 系模型的 SLO goodput 为最强基线的 2.4–2.9 倍。→ 价值：TBT 类 SLO 的吃紧根源是调度不留余量而非算力不足；「尾部校准的步级 prefill 预算」可平移到交互式 agent 网关的容量规划。｜来源：[arXiv:2611.18392](https://arxiv.org/abs/2611.18392)｜2026-11-13

## 今日判断

**① 技术上最值得跟进的 3 条**

1. **ModHarness-RL（11-13）**：harness 演化从推理期走向训练环内，Compression 与 Steering 两个程序接口把「模型看到什么、收到什么引导」变成可学习对象；对任何做 agentic RL 的团队，这是把脚手架纳入优化目标的第一份可参照实现，执行验证+历史重放的双保险设计可直接抄。
2. **《More Agents, More Samples, or More Thinking?》元分析（11-13）**：516 个配置、三种基线匹配口径的统一计账，结论是资源不匹配时多智能体的表观优势几乎全是采样效应；负收益下仍要上多 agent 的唯一理由是证据分区、外部验证或模型多样性——这三条同时是本周 Worse Together（11-11）与 /teamwork（11-13）结果的共同解释。

**② 对 harness 设计、模型选型、推理成本、研究方向的影响（判断）**

- **Harness 设计**：RL 训练环内的 harness 演化需要执行验证器与历史轨迹重放，不能只靠评估器打分（ModHarness-RL）；生产 harness 的更新要走「回归检查+人工批准」的资产化流程（Co-Sight Harness）；多智能体化前先跑资源匹配基线，正收益的验收条件按证据分区/外部验证/模型多样性三条核对（元分析）。
- **模型选型**：Qwen4-Max 与 Hy4 flash 的全部性能数字为厂商自报，选型前等第三方 harness 复测与开源权重落地；但定价结构（缓存命中价、任务级费用）本身可信且已生效，预算模型应把「单任务费用」而非「每 token 单价」作为一级指标。
- **推理成本**：多模态投机解码的接受率瓶颈被定位到视觉依赖 token（46%→22%），修复后 3.58× 无损加速；交互式服务侧，尾部校准调度用调度余量而非加卡换取 2.4–2.9× SLO goodput——两条路都指向「先调调度与起草器，再谈扩容」。
- **研究方向**：候选生成与确认采纳的分离正在成为自进化系统的公共结构（EGE 的非劣性检验、G-CAST 的受治理 checkpoint 切换、ModHarness-RL 的执行验证、Co-Sight 的回归门），差异只在治理强度；下一步的可比维度是谁的非劣性检验带统计保证。
