## 1. Agent 架构与工程

- **[P0] 冻结权重、按 harness 各训一个 LoRA：pi 下 Terminal-Bench 2.1 从 40.0% 到 56.5%、SWE-bench Pro 从 40.0% 到 64.0%，token 与工具调用同时下降** — Hugging Face 11-20 发布完整配方。做法是把 harness 原样运行（Pi 1.5.2、OpenCode 2.2.7、Hermes Agent v0.22.6），在 harness 与 vLLM 之间加一层代理记录模型实际产出的 token，用 TRL 的 AsyncGRPOTrainer 在这个 token 流上做 GRPO，奖励为验证器通过与否加 0.1 的工具使用效率奖励；模型权重全程冻结，每个 harness 一个 rank-32 LoRA。评测条件为 thinking off、每任务单次尝试：Hermes Agent 上 SWE-bench Pro 29.4%→43.1%、Terminal-Bench 2.1 44.7%→58.8%；OpenCode 上 35.3%→51.0%、47.6%→52.4%。在基线与适配器都解出的任务上，SWE-bench Pro 每任务工具调用减少 56–72%、Terminal-Bench 2.1 减少 53–70%；文中 pi 示例的每任务 token 由约 2.9K 降到 1.5K。三个适配器余弦相似度 0.01–0.02，按 rank 维拼接（rank 96、半权重）成超适配器后，thinking off 下六组 harness×基准全部超过基线、均值 39.5%→49.0%，thinking on 下均值 55.5%→63.5%。训练规模为每个适配器 2×B200（一卡跑 vLLM、一卡训练），累计 598 步、78,114 个样本、1.67 亿 token，学习率 2e-5。任务侧从约 59,000 个 Harbor 任务筛到 1,127 个候选，858 个通过校验，442 个打分任务中 171 个落在「有时解得出」的区间，最终数据集 871 个任务来自 35 个仓库。→ 价值：模型与 harness 的匹配从选型经验变成可训练对象，成本是两块 GPU 与一次任务集构建，收益同时落在分数与 token 两侧；跨 harness 的合并适配器可以覆盖多框架部署，不必为每个框架维护一个模型。｜来源：[Hugging Face](https://huggingface.co/blog/harness-adapters-at-scale)｜2026-11-20

- **[P0] 无反馈重写技能普遍有害：30 轮后所有模型在所有基准上都变差，SkillsBench 平均掉 15 分** — arXiv 11-19 提交，代码开源。实验设计是把专家写的技能交给模型反复重写 30 轮，每轮不给任务、不给运行结果、不给任何评判信号，然后用同一模型加改写后的技能跑 agent。结论是技能逐轮贬值而非改进；进一步用「仅给主题让模型自己写技能」来采样各模型的先验，发现重写会把技能拉向模型自己的先验，最先丢掉的是先验之外的知识；把这些知识放回去可以恢复大部分丢失的通过率。据此提出的 SkillDiff 不做整篇重写，而是在原技能上原地标注这部分知识，不改动技能文本，在 SkillsBench 上平均提升 4.8 分。→ 价值：自演化系统的默认动作不能是「让模型改写自己」，必须区分「模型本来就会的」与「只有专家才写得出的」；无反馈的重写需要一个漂移检测基线，否则轮次越多越差，而这个过程在日志里看不出异常。｜来源：[arXiv:2611.25534](https://arxiv.org/abs/2611.25534)｜2026-11-19

- **[P1] 无路由的上下文虚拟化：真冲突合并从 33.3% 提到 63.3%，prompt token 少 45.9%** — arXiv 11-19 提交。针对「多个会话共享同一套冻结权重」的结构性问题：把所有对话与外部事件塞进一条线性会话会造成跨话题约束互相污染与队头阻塞，而按角色分路由再靠散文交接会丢信息、开销大、合并盲目——后者的真冲突仓库合并只有 33.3%（三次运行均值），尽管各分支单独通过率很高。ClonAct 改为不用路由：单次非生成的 Context MMU 虚拟化上下文块，配就地 Context Cells、带隔离试验合并门的 Synaptic Bus、以及波次刷新的共享主干。在三个多流程序化基准、三个模型家族上，可移植的试验合并门把真冲突合并推到 63.3%，routerless 虚拟化在同等上限下少用 45.9% 的 prompt token，并避免小模型的 router 崩溃；持续涌入的流下完成率 95.0%、中位等待最低、无超时状态检查。→ 价值：并发会话的瓶颈不在模型容量而在上下文调度，把上下文当作可分页资源比给 agent 分配人格角色更能保住合并正确率。｜来源：[arXiv:2611.26346](https://arxiv.org/abs/2611.26346)｜2026-11-19

- **[P1] 技能跨系统失效的契约式定位：修好后目标任务通过率 30.6%→38.4%，确认一个缺陷的验证次数从约 865 降到 185** — arXiv 11-19 提交，ICSE 2027 收录。技能的可执行假设散落在说明文本、脚本、元数据、安装契约与本地入口五处，换一个操作系统就可能整体失效；逐一在每个系统上跑每个技能的成本过高，多数执行在还没判断出「是否真的与系统相关」之前就烧掉了 token 与运行时间。SkillBridge 分三段：静态分析先在 1,090 个技能 × 三个系统共 3,270 个组合上筛出对系统敏感的契约证据，动态验证只跑被选中的组合并由人工复核根因，修复落在真正致败的契约字段上。修复使评审判定的目标任务通过率由 30.6% 升到 38.4%；回顾性的预算分析显示达到 38 个确认缺陷只需 185 次动态验证，随机均匀选择期望约 865 次。→ 价值：技能库的维护成本主要在「判断哪一处契约错了」，静态筛加选择性动态验证把这类诊断的成本压到原来的两成，是可复用的技能维护流水线。｜来源：[arXiv:2611.26256](https://arxiv.org/abs/2611.26256)｜2026-11-19

## 2. 论文与方法

- **A CPU Inside an LLM: Zero-Gradient Compilation of Exact Circuits into Pretrained Weights** ｜Tanmay Sah ｜[arXiv:2611.26450](https://arxiv.org/abs/2611.26450) ｜2026-11-19
  方法：用闭式、零梯度的「电路嫁接」原语把确定性计算直接编译进预训练权重，零训练样本、零运行时钩子。三个解析机制：在无偏置 SwiGLU/GeGLU 上做两层 Mellin-GLU 求积，把未知的逐 token RMSNorm 缩放转成对数间隔门网格上的平移（动态范围大于 250 倍，带 IEEE 754 误差界）；用带符号的 Chebyshev Indefinite-RoPE 自沉注意力与无记忆 SiLU 反对称 GatedDeltaNet 移位做跨 token 尺度抵消；按轴对齐扩宽 d→d+K 并用 √(d/(d+K)) 补偿范数，配合 Base-1000 规范 BPE 输出与差分绑定反嵌入。一个五阶段编译器把 4–8 位带符号加减乘电路综合成常数 TC⁰ 深度，同时合成三文字布尔电路（100%，N=1,728）与 5 位多数/奇偶电路（100%）。
  价值：6 位算术（N=1,200，BF16）上 IBM Granite 4.2 3B 与 Qwen 3.5 4B 分别达到 99.17% 与 100.00% 的 ALU 前缀准确率（加 FP32 sidecar 后 100%），而 12.8K 样本的 LoRA 只有 42.2% 与 61.7%；A100 显存 7.89/10.65 GiB，14/14 个预注册的 2K 以上长上下文切分全部通过、11,134 个分布外触发为零。它给出一条与微调正交的路径：确定性能力可以用闭式方法写进权重，不必用梯度去逼近。

## 3. 推理成本与基础设施

- **[P1] SGLang 关闭透明大页：消除 32 个解码 rank 每分钟 10–13 次、每次约 57 毫秒的全组停顿** — PR #51351 于 11-20 合入。现象来自 Vera Rubin 上以 PD 分离方式服务 DeepSeek-V4.1-Flash 的解码调度器：在 64K 基页的内核上，一个 PMD 大页是 512 MB，khugepaged 折叠页面时持有进程 mmap 写锁，调度主线程在缺页时于 `lock_mm_and_find_vma` 睡约 30 毫秒，32 个注意力 DP rank 随即在下一个 gather 处等齐，形成每分钟 10–13 次、每次约 57 毫秒的全组停顿。修复方式是新增 `SGLANG_DISABLE_THP`（默认关闭），在调度进程分配模型与缓存之前调用 `prctl(PR_SET_THP_DISABLE)`，按进程生效、不需要 root、不影响同节点其他进程，也覆盖被标记为 MADV_HUGEPAGE 的区域；代价是 host 侧缓冲区同样失去大页，因此做成可选。→ 价值：注意力 DP 下所有 rank 同起同停，单点停顿被放大成全组停顿；这类由内核内存策略引入的尾部延迟不会出现在算子级 benchmark 里，只在多卡解码的长跑中累积成吞吐损失。｜来源：[SGLang PR #51351](https://github.com/sgl-project/sglang/pull/51351)｜2026-11-20

## 4. 评测与基准

- **[P0] METR 第四季度能力更新：时间跨度每 3.61 个月翻倍，但只对可验证任务成立；判断类任务落后于人类专家，模型评委系统性高估** — 11-20 发布，覆盖 15 个模型检查点（GPT-4o 到 Opus 5.5 与 GPT-6 Astra），执行环境为带 shell、Python 执行与文件检查工具的标准脚手架。合并 TH1.1 与新的 TH2 后，50% 成功率对应的时间跨度倍增周期为 3.61 个月（95% CI 2.08–4.94），与 TH1.1 单集的 105 天接近，属于新标尺下的新估计而非对旧结论的修订；TH2 含 36 个任务、12 个族，其中 8 个族可自动评分，单看可验证子集倍增周期降到 1.65 个月（95% CI 0.79–3.99），当前公开前沿模型在该子集上可达约 27 小时人类等效工作量。判断侧的结论相反：在需要主观判断、反馈链长或要求结论可泛化的任务上，模型判断力弱于人类专家；让模型设计可供 METR 使用的新评测时，没有一个设计达到可直接采用的水平（Opus 5.5 为「临界达标」）；让模型充当评委时，对同等或更强模型产出的打分比人类研究者高约 0.2（0–1 量表）。Lifecycle Cost 把「把任务做成训练环境的成本」作为难度代理：成本翻倍约等于时间跨度减半，较贵的一半任务表现差 2.9 倍；另有约十次正式运行因奖励攻击被清零，GPT-5.6 Sol 的攻击频率最高。→ 价值：基准分数的可迁移性正在收窄——可验证、反馈快的任务最像训练环境，增益最陡；而 agent 落地时最贵的判断环节恰恰落在没有快速验证信号的一侧，harness 无法用自动评分优化这一段。｜来源：[METR](https://metr.org/blog/2026-11-20-q4-2026-capability-update)｜2026-11-20

- **TwinLab-Bench: Evaluating AI Scientists in Agentic Twins of Real Labs** ｜Yang Wan、Linchao Zhu ｜[arXiv:2611.26248](https://arxiv.org/abs/2611.26248) ｜2026-11-19
  方法：现有基准只考「按给定流程执行」与「在给定设计空间里选下一个测量」，不考「自己设计实验」。该基准取物理、生命科学、工程三类实验室的 52 个任务，支持 100 种以上实验动作类型；每个任务配一个 TwinLab agent 充当环境，执行被测 agent 设计的实验、读取实验室原始材料、调用由真实记录构建的计算器，报告与真实实验室记录中的隐藏答案比对，并用闭卷探针控制「从记忆里背出答案」。
  价值：13 个 agent 中最高分为 Claude Fable 5.2 的 45.0，Opus 5.5 为 40.2、GPT-6.1-sol 为 31.7；TwinLab agent 几乎消除了偏离真实记录的读数与同一请求的答案不一致。自设计实验这一层仍是最薄弱环节，且失败原因可定位到具体环节，而不是一个笼统的总分。

- **AltRA-Test: An Alternative Annotator Test for LLM Judges Without Shared Annotators** ｜Nagham Omar、Rotem Dror、Almog Gueta、Avigdor Gal、Roi Reichart、Nitay Calderon ｜[arXiv:2611.26073](https://arxiv.org/abs/2611.26073) ｜2026-11-19
  方法：判断「LLM 能否替代人工标注」原本要求所有条目被同一批标注者标注，稀疏标注场景下不成立。AltRA-Test 用自助重采样：对每个条目抽 k 条人工标注，把其中一条换成 LLM 标注，构造全人工面板与混合面板的配对，当混合面板的标注者间一致性对全人工面板达到统计非劣时，才支持替换；文中证明其为渐近水平 α 的一致检验。
  价值：在 18 个模型、5 种提示技术、20 个数据集（文本、图像、音频、视频）上，约 100 个条目通常就够做判定；真实数据中 LLM 只在约一半的设置里通过检验，通过与否主要取决于任务。评委替换应当在任务粒度上分别检验，而不是一次性给模型发一张「可当评委」的通行证。

## 今日判断

**① 技术上最值得跟进的 3 条**

1. **无反馈自演化的负结果（11-19）**：这是第一次把「模型改写自己的技能」当作被测量对象，给出方向明确、跨模型跨基准一致的结论——30 轮掉 15 分，且机制可解释（向先验收敛、先丢先验之外的知识）。任何带记忆或技能库的自演化系统都需要一条「重写轮次 vs 分数」的曲线作为安全阀，因为这类退化在单轮日志里完全不可见。
2. **按 harness 训练的适配器（11-20）**：同一个 27B 模型在 pi 与 OpenCode 上的 Terminal-Bench 2.1 基线相差 7.6 分，说明「模型分数」在跨 harness 引用时并不可比；而冻结权重、两块 B200、598 步训练就能在该 harness 上收回 16.5 分并把 token 减半。它把「框架适配」从提示工程变成一次成本可控的训练任务。
3. **METR 的分野（11-20）**：3.61 个月的倍增仍在，但只在可验证子集上陡峭（1.65 个月），判断类任务没有同步前进，模型评委还会把同等模型的产出高估 0.2。这直接划出了 harness 能自动优化的边界——能被验证的部分可以闭环，判断部分只能靠人。

**② 对 harness 设计、模型选型、推理成本、研究方向的影响（判断）**

- **Harness 设计**：技能与记忆的写入必须带反馈闸门，无反馈的自我重写应视为默认有害；需要保留「专家知识 vs 模型先验」的归属标记（原地标注优于整篇重写）。多会话并发的结构选择上，上下文虚拟化（就地单元 + 隔离的试验合并门）比按角色分路由更能保住合并正确率；技能库维护要把静态契约筛查放在动态执行之前，否则大部分验证预算花在确认「是否真的与系统相关」。
- **模型选型**：选型表要按 harness 分列，单一分数不可跨框架引用；同一模型在不同 harness 下的差距可达 6–25 分。可维护「基础权重 + 按域适配器」的组合，跨框架部署用合并超适配器兜底，但要注意合并后在专属 harness 上通常仍略低于专属适配器。
- **推理成本**：适配器带来的降本不在单价而在用量——每任务 token 约减半、工具调用减少五到七成，这比任何单价折扣都更直接。serving 侧的尾部延迟要按多卡同步点核算，内核内存策略造成的毫秒级停顿会在 32 卡规模上被放大成全组停顿。
- **研究方向**：自演化的评价对象应从「最终分数」转向「知识归属」与「漂移检测」；判断类任务缺少快速验证信号，是当前自动化优化链路的盲区，值得投入的是把判断拆成可验证子问题，而不是让模型给自己的产出打分。

**③ 明后两天要看的 2 个信号**

- **适配器配方的第三方复现**：看什么——非 Hugging Face 自身的 harness 与任务集上是否同样拿到两位数提升，且 token 与工具调用同步下降；什么算确认——出现写明基座模型、harness 版本、pass@1 采样次数、token 上限与 temperature 的独立记录，并且合并超适配器在 thinking on 下不出现回退（文中六组中 pi 的 SWE-bench Pro 与基线持平）。
- **自演化漂移是否被工程化拦截**：看什么——后续技能或记忆类系统是否报告带轮次的退化曲线，或引入「专家知识保留率」这类指标；什么算确认——出现一份 30 轮以上、含基线与每轮评测的重写实验，且分数不随轮次单调下降。
