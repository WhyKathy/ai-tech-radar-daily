## 1. Agent 架构与工程

- **[P0] Google 公开 Antigravity /teamwork 的方法与战果：上下文按构造分区、批评者在干净上下文里复核，28,800 次子 agent 调用产出 180 万行 Lean** — Google Research 11-13 发布（作者 Vahab Mirrokni），针对语言模型两个弱点分别给方案：生成不可预测用「并行探索 + 专用证伪器」，多日任务丢失上下文用「按构造分区」——每个专职 agent 只拿到该步骤需要的文件与工具，协调者把任务交给全新后继者，critics 与 auditors 在不带原始生产者推理的干净上下文里挑战与验证。证伪器按领域换：数学用 Lean 4 证明检查器，软件跑未经修改的测试套件，另有执行模拟器、网页检索、硬件性能计数器。工作流写成「声明式自我改进的自然语言模式」，按提示动态路由到 /boost（顺序「求解—验证」循环）、Long Proof、Deep Review 等模式。数字：2013 年 Courtade–Kumar 猜想先被归约为 14 变量优化问题、再全一般性形式化，约 5,000 万行 Lean 4；Weil 猜想由 /teamwork-LEAP 全自主端到端形式化，约 180 万行 Lean、跨 28,800 次子 agent 调用；Hilbert 第十问题（整数环）首个形式化逾 91.9 万行。工程侧：两周内把 Fuchsia Zircon 微内核剩余 C++ 重写为约 80 万行安全 Rust 并通过内核单元测试、在 arm64 启动；libgav1 重写为约 17 万行 Rust 且位精确一致，初始慢 4 倍、优化后比原 C++ 与手写汇编快 20–30%；9×9 围棋引擎自对弈加速 2,300×、不到 8 天提升约 2,600 Elo 至 1,885（介于 KataGo 16 与 32 visits 之间）；DuoDiscover 用 23 秒代理评估器替代 7–32 分钟整机评估，JAXBench 17 个内核几何平均加速 4.09×。另有 30 个 agent 借物理光谱模拟器从 NMR 反推分子结构，top-1 95%、top-3 100%，约为单 agent 的两倍。Deep Review 在 STOC 2027 投稿中获 578 篇（超三分之一）试用，70 人调查里 90% 认为反馈基本属实、逾 30% 称发现实质性证明漏洞。工具已向 1 万名学术研究者开放 6 个月最高额度。→ 价值：把「生成—反驳—验证—整合」拆成可复用的角色与接口，且明确了三个可迁移的决定——上下文按步骤切、批评者与生产者隔离、验收器不由生成方提供；这批数字同时说明瓶颈已从「能不能证」转到「规格与命题翻译对不对」。｜来源：[Google Research 官方博客](https://research.google/blog/advancing-science-engineering-with-antigravitys-teamwork-feature/)、[虎嗅（分项数字与谨慎解读）](https://www.huxiu.com/ainews/16314.html)、[IT之家](https://m.ithome.com/html/1027140.htm)｜2026-11-13

- **[P0] Termination Lag：38–82% 的成功运行在首次编辑就写对，但中位 35–60% 的步骤花在正确补丁之后，1–8% 的运行把对的改回错的** — arXiv 11-11 提交（Musa Cim、Burak Topcu、Mahmut Taylan Kandemir）。方法是对执行过程中的每一个不同仓库补丁都记录并单独测试，从而定位「首个正确补丁」到运行结束之间的步数。覆盖 5 个模型、2 个 agent 框架、3 个 SWE-bench 数据集：38–82% 的成功运行在最初的源码编辑上就已正确；此后仍继续消耗大量步骤，在 SWE-bench Verified 与 Multilingual 的成功运行中，解后步骤占中位 35–37%（Qwen3-Coder）与 54–60%（Laguna-XS.2），内容以自我验证与仓库探索为主；1–8% 的情况下这段继续活动把先前正确补丁撤销，最终答案反而错误。→ 价值：给出可直接落地的判据——在首次全绿或首次通过自检时冻结补丁快照、把后续步骤降级为只读验证，能同时砍成本与消除「改回错的」这一类静默失败；也说明「多步验证」并非免费的正确性保险。｜来源：[arXiv:2611.14960](https://arxiv.org/abs/2611.14960)、[arXiv cs.AI 新投稿列表](https://arxiv.org/list/cs.AI/new)｜2026-11-11

- **[P1] EvoTrias：把「治理 / 提案 / 判定」三权分立，治理与提案拆开后 token 成本降 64%** — arXiv 11-11 提交。论点是把程序演化的三个决策分开归属：Structured Governance 管跨轮次的搜索方向，Open Proposal 管任务内的候选构造，Protected Judgment 由私有评估器独占，三者只交换带类型的契约，边界由运行时钩子加固；该结构可作为插件把现有编码 agent 变成演化系统。结果：数学、系统与算法设计基准上取得最好成绩；治理与提案分离使 token 成本降 64%；Open Proposal 让演化扩展到 68 万行的工业级仓库；Protected Judgment 使榜单分数与迁移表现保持一致。→ 价值：直接指向自进化系统的常见病——控制器越权挤压提案自由度、评估器与生成方同源导致分数虚高；三权分立加私有评估器是一个可先落地的最小改造。｜来源：[arXiv:2611.15309](https://arxiv.org/abs/2611.15309)｜2026-11-11

## 2. 论文与方法

- **Discovering Effective Agent Memory Designs through Program Evolution（MAPE）** ｜未标注机构 ｜[arXiv:2611.17068](https://arxiv.org/abs/2611.17068) ｜2026-11-12
  方法：从最小种子出发，用统一的生命周期接口与「诊断—提案」迭代循环演化整个记忆程序（而非只调参数），在 LoCoMo 与 LongMemEval 上以准确率与 serving 成本为联合目标。
  价值：相对人工设计基线最高 +12 个绝对百分点，而 serving 成本只有 35%；蒸馏出两条可复用模式——把原始对话保留为可检索证据以补回抽取记忆丢失的细节，以及按查询意图重组检索到的证据；把「组合模块」移植进 5 个既有记忆系统后全部提分。检索目标本身会改变算力落点：同时优化成本时，计算从「用 LLM 构建记忆」移向「查询时选择性处理」。代码已放。

- **EvoX: Rethinking the Agent Harness as a Runtime Policy** ｜未标注机构（Rust 实现）｜[arXiv:2611.15006](https://arxiv.org/abs/2611.15006) ｜2026-11-11
  方法：把 harness 当作补充模型「语义策略」的「运行策略」，用三个机制落地——Action Realization（工具调用不匹配时的实现层兜底）、Execution Continuity（中断工作流的续接）、Outcome Grounding（把「声称完成」落到证据上）；配套 Contrast 评测框架，含显式公平约束、面向提供方的请求校验与基于证据的裁定。
  价值：5 个基准、6 个基础模型、6 个 harness、691 个共同 task–model 对上最高成功率 56.2%，比其余五个 harness 均值高约 3.0 个百分点；在 GLM-5.3 上 +10.7、Kimi K3 上 +7.9，且未使用记忆、演化或扩展件——说明 harness 收益高度依赖模型，跨厂商套用不成立。

- **guardscope: Measuring Which Actions Runtime Controls Check in LLM Agent Systems** ｜未标注机构 ｜[arXiv:2611.15223](https://arxiv.org/abs/2611.15223) ｜2026-11-11
  方法：一个控制点只能检查经过它放置位置的动作，而 agent 起作用的路径多于工具调用通道。guardscope 分两阶段：静态阶段从源码预测某个控制能覆盖 15 条动作路径中的哪几条；经验阶段在 8 种拓扑之一的部署上跑固定负载，把每个实际执行的动作与内核级 ground truth 对账，判定为已检查、被绕过或被阻止。
  价值：让「控制覆盖了哪些路径」这件事可被第三方核验，而不是由厂商自述；实验覆盖两个 agent harness 与真实运行时控制（含微软 agent governance toolkit、agentgateway），可直接用于验收 agent 网关的实际防线。

## 3. 推理成本与基础设施

- **[P1] MACaQ：MXFP4 W4A4 逐层独立量化，122B 模型 64 分钟、峰值 32.5GB 显存，推理端仅 2.3% 额外开销** — arXiv 11-07 提交、11-11 修订（v2）；华为 CSL，代码在 huawei-csl/MACaQ。做法是让每个线性层独立：对激活在线施加 per-channel 缩放与块 Hadamard 变换，把逆变换吸收进权重，因此无需跨层传播基变换，量化过程可流式执行、内存里只驻留一层；再用 Flip-Refinement——一个 Hessian 感知的坐标下降过程，贪心地把单个 FP4 码移到相邻可表示值，取代 round-to-nearest。数字：在 vLLM 上对 Qwen3-32B，相对纯 MXFP4 的端到端额外开销 2.3%；perplexity 低于 DuQuant++ 与 MR-GPTQ，在 Llama-3-8B 上以 1/11 的量化时间追平两者最好 perplexity；122B 模型 64 分钟完成量化、仅用 32.5GB 显存；同一套层局部设计未做架构改动即用于图像扩散模型。→ 价值：把「模型装不进单卡」这一约束从「换硬件」改成「先量化」——量化时间从跨天降到一次午休，迭代频繁的团队不必为每次换模型预留长窗口；但论文自述跨层误差补偿被放弃、MoE 实验只量化专家层、0.6B 规模上在线变换开销升至 8%，小模型与生成式任务的收益需另测。｜来源：[arXiv:2611.10649](https://arxiv.org/abs/2611.10649)、[论文逐表解读](https://jaehun.me/en/posts/paper-2611-10649)｜2026-11-07（11-11 修订）

## 今日判断

**① 技术上最值得跟进的 3 条**

1. **/teamwork 的角色与上下文划分（11-13）**：这是目前公开材料里最完整的「多日、多 agent、带独立验收器」的工程实现说明，且给出了三个可独立抄走的设计决定——上下文按步骤切分而非压缩、批评者在干净上下文里工作、验收器由外部工具承担。5,000 万行 Lean 这个数字本身不可复现，可复现的是接口与角色边界。
2. **Termination Lag（11-11）**：把「早解晚停」变成可测量的步数区间（38–82% 首次即对、中位 35–60% 后续浪费、1–8% 改回错误），是近期对单 agent 运行成本最有操作价值的一篇——不需要换模型，改的是停止判据。
3. **EvoTrias 的三权分立与 64% token 降幅（11-11）**：自进化系统最容易被忽略的一环是评估器独立性；这篇把治理、提案、判定的归属拆开并给了成本量化，适合作为演化框架的最小改造项。

**② 对 harness 设计、模型选型、推理成本、研究方向的影响（判断）**

- **Harness 设计**：停止条件应写成「首个全绿即冻结补丁」，后续步骤只读验证；多 agent 编队里批评者与生产者必须上下文隔离，否则批评退化为自我辩护；运行时控制要按「动作路径」而非「工具调用」盘点覆盖率，网关前的静态预测加内核级对账可以作为上线前的验收动作。
- **模型选型**：同一 harness 在不同模型上的收益差可逾 10 个百分点（EvoX 的 GLM-5.3 与 Kimi K3 分项），harness 与模型必须配对评测，不能把某个 harness 的成绩外推到另一家模型；数学推理类任务要同时看单题成本，Carbon 在 high 档的领先对应约 15 倍账单，且部分分数为估计值。
- **推理成本**：量化正在从「离线整备」变成「例行操作」——单卡 64 分钟、32.5GB 峰值即可把 122B 压到 4 bit，配合 2.3% 的推理端开销，让「装不进单卡」不再等于换硬件；但小模型与长生成任务的额外开销与精度损失要单独测。
- **研究方向**：记忆设计开始被当作可演化对象（整程序演化、成本与准确率联合目标），而不是固定组件；「演化什么」与「谁判定」正在被拆成两个独立问题，后者对榜单可信度的影响大于前者。

**③ 明后两天要看的 2 个信号**

- **NVIDIA 11-17 财报（临时 CEO 任内首份）**：看什么指标——FY2027 Q3 营收相对约 1,090 亿美元一致预期的偏离、FY2028 指引口径、数据中心分部毛利率；什么算确认——电话会给出下季度指引且不下调，5,000 亿美元融资平台被点名或被回避。
- **/teamwork 工件是否落地**：看什么指标——1 万名研究者的 6 个月额度申请入口是否开放、Lean 工程与规格是否随论文公开、STOC 2027 的 Deep Review 反馈是否被第三方复核；什么算确认——出现可下载的工件仓库或独立团队的复跑报告。
